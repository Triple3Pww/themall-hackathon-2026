# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Hackathon workspace for the MUICT × The Mall Hackathon 2026 (brief: `MUICT_THE_MALL_Hackathon_2026-Project-Brief.pdf`). The project is **No Cap – ป้ายนี้ไม่มีหลอก**: contention-aware parking signs placed before each floor's turn-off on a one-way up ramp. Git repo, remote `Triple3Pww/themall-hackathon-2026` on GitHub. Three working areas:

- `nocap/` — the Python core logic (the only real code with tests).
- `slides/` — pitch deck, generated by patching raw PPTX XML. The team's presented deck is a Canva design (`มี ≠ ได้.pdf` is its export), edited separately from this build.
- `mockups/` — standalone HTML mockups of the sign UI (`mockup.html`, `nocap-3d.html`); PNG screenshots of them are fed into the deck. `mockups/video/` holds MP4 clips recorded from `nocap-3d.html`, made by the scripts in `mockups/tools/`.

**Never claim the mall already counts cars at the ramp.** It has per-bay sensors only; the ramp counting cameras are what No Cap adds.

The loose `.docx`/`.pdf` files at the root are application forms and reference material, not inputs to any code. Files starting with `~$` are Office lock files — ignore them.

User-facing text (sign labels, deck copy) is in Thai.

## nocap: commands

Run from `nocap/` (a `.venv` with Python 3.14 and pytest already exists; project requires Python ≥3.11, only runtime dep is `pyyaml`):

```sh
.venv/bin/pytest                                   # all tests
.venv/bin/pytest tests/test_decide.py::test_raw_advice   # single test
.venv/bin/pip install -e '.[dev]'                  # fresh setup
```

`pyproject.toml` sets `pythonpath = ["."]`, so tests import `nocap.*` without installing.

## nocap: architecture

Pipeline per floor, all pure functions/dataclasses in `nocap/core/`:

1. **`FloorReading`** (`model.py`) — raw inputs: `occupied` from existing bay sensors, `cars_on_floor` from ramp cameras (in − out), `sensor_coverage`, timestamp.
2. **`compute_floor_state`** (`contention.py`) — the key idea: `circling = cars_on_floor − occupied` (cars on the floor hunting for a bay), `effective = free − circling`. Returns `FloorState(valid=False, reason=...)` whenever data is untrustworthy (`no_data`, `stale`, `low_coverage`, `occupied_out_of_range`, `cameras_below_parked`, `circling_exceeds_capacity`). Small negative circling (within `max_inconsistency`) is clamped to 0 as jitter. `effective` may be negative internally; `display_effective` clamps to 0 for the sign.
3. **`raw_advice`** (`decide.py`) — `GO` / `UP` / `NO_ADVICE` for the sign before floor `here`, given `here` and the floor `above`. Deliberately biased to `GO`: `UP` only when `here.effective <= low_threshold` AND `above` beats it by `margin_up`, because a wrong UP is irreversible on a one-way ramp. Top floor always `GO`; either floor invalid → `NO_ADVICE`.
4. **`SignController`** (`decide.py`) — stateful hysteresis wrapper. GO↔UP needs the new advice held `hold_seconds` *and* the current shown for `min_dwell_seconds`; switching *to* `NO_ADVICE` is immediate ("honesty beats stability"); from `NO_ADVICE` needs only `hold_seconds`. Starts in `NO_ADVICE`. Records every change in `flips`.

`nocap/config.py` loads `config/mall.yaml` into `MallConfig` (floors listed bottom→top in ramp order; `above(floor_id)` gives the next floor up). Threshold defaults live in both `Thresholds` (`model.py`) and `mall.yaml` — keep them in sync. There is no I/O layer, sensor adapter, or sign driver yet; only the core logic.

## slides: deck build

```sh
cd slides && python3 build_deck.py   # writes No_Cap_Pitch_Deck.pptx
```

`build_deck.py` does string/regex surgery on the XML in `slides/unpacked/` (an extraction of `No_Cap_Pitch_Deck_original.pptx`): it inserts new slides 12–14 (mockup, implementation plan, future-ready), copies `mock-driver.png` / `mock-wide.png` into media, renumbers kickers/footers (`NN / TOTAL`), replaces specific Thai text (guarded by `assert`s), reorders `presentation.xml`, then re-zips.

It **modifies `unpacked/` in place and is not idempotent** — to rebuild, re-extract the original first:

```sh
cd slides && rm -rf unpacked && mkdir unpacked && unzip -q No_Cap_Pitch_Deck_original.pptx -d unpacked && python3 build_deck.py
```

`render/new.pdf` and `render_orig/orig.pdf` are PDF renders of the new and original decks for visual comparison.

## mockups: the 3D simulation (`nocap-3d.html`)

One self-contained page: Three.js r128 from a CDN, no build step, open it straight from disk. It models floor P3 (32 bays in 4 rows), the one-way up ramp, the sign on its gantry before the turn-off, and the two counting cameras (entrance at z=−6, exit at z=−22). Its sign rule is the same as `nocap/core/decide.py` (`LOW_THRESHOLD = 1`, `MARGIN_UP = 8`); `compute()` holds the subtraction. Keep the two rules in sync.

Bottom-bar controls: add/remove cars, auto traffic, **มุมคนขับ** (driver's seat looking at the sign), **มุมกล้อง CCTV** (the counting camera's feed, with tracker boxes, the counting line and a "how it counts" panel), camera fault (sign goes to ไม่แนะนำ), the HUD, and **ระบบเดิม** (bay sensors only, no cameras).

**จำลองช่วงรถแน่น** is a click-through scenario. Each step freezes the garage and waits for ถัดไป, → or PageDown, so a presentation clicker can drive it. The same moment is played twice: P3 has 4 free bays and **4 cars already circling**; you come up the ramp.

- **Round 1 (old system):** the sign says เข้าได้เลย, you turn in, the 4 circling cars take the 4 bays, and you circle out to P4.
- **Round 2 (No Cap):** step 1 is four counting sub-steps (`countBeat1`–`4`, labelled วิธีนับ 1/4…4/4).
  1. Cut to the entrance CCTV. A replay shows 6 cars coming up the ramp: 4 turn in and cross the line (+1 each), 2 stay on the ramp to P4 and are not counted. Entrance count goes 28 → 32.
  2. Bay sensors pulse: 32 on floor − 28 parked = ?
  3. The 4 circling cars get numbered: = 4.
  4. ว่าง 4 − วนหา 4 = เหลือจริง 0, so the sign says ขึ้นชั้นบน.
- **Result:** distance and time from the sign to the P4 ramp, for both rounds.

The camera cuts to the driver's seat automatically when your car nears the sign (`DRV_CUT_I`), and goes back to the overview after the decision step. The story box's caption text (`#story .t`) is hidden on purpose — the presenter narrates; only the step line, number boxes and buttons show.

## mockups: recording the step videos

```sh
cd mockups/tools
node record-steps.js <path-to-playwright-package>   # plays the scenario headless on the GPU, saves frames to ./rec (git-ignored)
python cut-clips.py                                  # cuts ./rec into ../video/NN-<step>.mp4 (needs ffmpeg)
```

The output is 11 clips at 1920×1080, 30 fps, one per step. Each clip runs from the click that left the previous step to 3–4 s after this step finishes, so they play back to back seamlessly. Recording must be **headless with `--use-angle=d3d11`**: a headed window is cropped by the screen size, and SwiftShader renders at only ~25 fps. Car motion varies a little per run, so the distance and time in the result step change between recordings. If you change the scenario's steps, update `NAMES` in `cut-clips.py` (it asserts the count).
